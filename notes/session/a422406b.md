# Plan: Evaluate Wayland Display Server Options for Alpine Guest

## Context
The ShaderToy viewer deployment to Alpine guest failed because GLFW requires a display server (X11/Wayland), which doesn't exist in the headless Alpine VM. Currently working demos (triangle, vkcube) use GBM + VK_KHR_display for headless rendering.

## Task
Research Smithay and related Wayland compositor projects to determine if they can provide a lightweight display server solution for the Alpine guest, enabling GLFW-based applications to run.

## Phase 1: Exploration Complete ✓

### Current Architecture Findings
- **Working demos**: triangle and vkcube use DRM directly (no display server needed)
- **Pipeline**: Guest Vulkan → Venus → virtio-gpu → QEMU → MoltenVK → Metal → macOS
- **Key mechanism**: QEMU handles presentation on host side via IOSurface + CAMetalLayer
- **Zero-copy path**: GBM blob → Vulkan via VK_EXT_external_memory_dma_buf → DRM scanout
- **GLFW failure root cause**: Requires X11/Wayland display server that doesn't exist in headless Alpine

### Smithay & Related Projects Status (2026)

**Smithay Library** ([active](https://github.com/Smithay/smithay)):
- Actively maintained (commits as recent as Jan 26, 2026)
- Modular toolkit for building Wayland compositors in Rust
- Used by COSMIC desktop (Pop!_OS 24.04 LTS, Dec 2025)
- Recently ported to Redox OS (Nov 2025)
- Includes "anvil" sample compositor

**Penrose** ([X11 only](https://github.com/sminez/penrose)):
- X11 window manager library in Rust
- No Wayland support (not a priority)
- Not applicable for this use case

**Way Cooler** ([discontinued 2020](http://way-cooler.org/blog/2020/01/09/way-cooler-post-mortem.html)):
- Wayland compositor project abandoned
- Rust bindings (rust-wlc) deprecated
- Not viable

**COSMIC Desktop** ([beta on Alpine](https://wiki.alpinelinux.org/wiki/Cosmic)):
- Rust-based desktop using Smithay compositor
- Available in Alpine Edge/community repo
- Systemd-independent (good for Alpine)
- Full desktop environment (heavyweight for VM)

## Phase 2: Design Complete ✓

### Wayland Compositor Options Analysis

**Weston** ([reference compositor](https://www.collabora.com/news-and-blog/news-and-events/weston-12-highlights-and-changes.html)):
- Minimal, mature Wayland compositor
- DRM backend for embedded systems
- Version 14.2 (Jan 2026) with hardware underlay planes
- Resource cost: ~20MB RAM, adds compositor layer
- Status: Production-ready

**TinyWL** ([minimal example](https://github.com/swaywm/wlroots/tree/master/tinywl)):
- Minimal viable Wayland compositor (~500 lines)
- Based on wlroots library
- Educational starting point
- Resource cost: ~10MB RAM
- Status: Example code, not production

**Alternatives Considered:**
- wlroots with headless backend (surfaceless rendering)
- wxrd (XR compositor for headless)
- Games On Whales headless Wayland setup

## Phase 3: Review & Analysis ✓

### Recommendation: **DRM-Only Approach (No Compositor)**

After comprehensive analysis, the best solution is to **refactor shadertoy_viewer to use DRM directly** like the existing working demos (triangle, vkcube).

**Rationale:**
1. **Architectural Alignment**: Matches proven Venus/virtio-gpu pipeline
2. **Zero Overhead**: No compositor adds ~0MB RAM vs. 10-40MB
3. **Performance**: Direct rendering path already achieves 47 FPS zero-copy
4. **Consistency**: Same pattern as triangle/vkcube demos
5. **Simplicity**: Reuse existing DRM/GBM infrastructure
6. **Project Goals**: Focus is testing Venus pipeline, not desktop environments

**Key Insight from Code Review:**
- `test_tri.c` (lines 44-108): Clean DRM/GBM initialization pattern
- `vkcube_anim.c` (lines 79-109): Double-buffered animation loop
- shadertoy_viewer.cpp: GLFW only used for window/input, Vulkan logic is portable

### Why Not Wayland Compositors?

**Smithay/COSMIC**:
- ❌ Heavyweight (40+ MB), full desktop framework
- ❌ Adds maintenance complexity
- ❌ Overkill for testing graphics pipeline

**Weston**:
- ⚠️ Viable fallback if DRM approach fails
- ⚠️ 20MB overhead, compositor latency
- ✅ Mature, embedded-focused

**TinyWL**:
- ❌ Example code, not production-ready
- ❌ Still requires compositor maintenance
